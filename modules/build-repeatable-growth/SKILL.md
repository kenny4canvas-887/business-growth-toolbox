# K3 找增长瓶颈（build-repeatable-growth）

> 这是 BMI 业务增长工具箱的八个阶段模块之一，回答「同一增长单元的获客、留存或增购能否重复」。
> 前置：只有根 `SKILL.md`（业务体检）已确认 `action_stage=K3` 时，才由它加载本模块。本模块不重新诊断阶段，不自行修改 `action_stage`，不调用其他阶段模块。
> 收口：定位瓶颈后回传业务体检，复核是否进入 K4。

## 触发边界

只有 `action_stage=K3` 已由业务体检 确认，且用户请求本轮增长分析、完整报告或正式测试时，才使用本模块。

用户明确请求优先于默认流程与展示偏好。复用交接证据，不逐步重复确认；已读取且未变更的参考不重复加载。证据闸门仍须满足，发布、部署和全局同步须另获授权。若本模块规则导致暂停或偏离请求，链接具体规则并说明原因。

本模块不重新诊断阶段，也不自行修改 `action_stage`。它只返回“继续 K3、返回 K2、返回 K1、停止或建议复核 K4”，最终阶段由业务体检 重新判断。

K3 只处理已经验证客户价值之后的增长问题：固定一个增长单元，识别增长瓶颈，并形成一个可验证的增长方向。以下工作不在本模块内完成：

- 从零进行客户定位或新客户需求验证；这属于 K1。
- 重新设计尚未成立的价值主张、产品方案或最小交付；这属于 K2。
- 完整商业模式、收入成本对比、资源调用与规模承接；这属于 K4。

## 专项分析优先

工具图默认交付：完成本轮专项回答时，按[视觉规则](references/visual-frameworks.md)同步生成一张已填写的商业模式九宫格：高亮本轮关键要素及其联系，未研究格保留灰色标记。工具图是帮助理解分析的独立产物，不以索要完整报告为前提；用户明确只要文字时除外。只画本轮已有结论，缺口照实标记，不为出图延长提问或扩大分析。

用户只研究商业模式九宫格中的关键要素时，将九宫格作为关系框架，按方法参考深挖与当前决定有关的要素；不强制四域图、增长实验或三张行动卡。此规则优先于下文默认完整交付与“每次进入K3”的展示要求；正式完整阶段测试仍执行原契约。用交付参考中的关键要素设计底稿保留细节，不为完整感拼凑九格。

先复用已验证客户价值，说明具体客户如何经由具体渠道获得、交付并持续实现价值。渠道不能只写线上／线下；继续追到平台或场所、触点、转化动作、交付衔接及依据。To B 复用K2按角色确认的成果与顾虑，检查它们怎样影响接触、审批、采用或续约，不把动机假设升级成事实。

阶段闸门与权限保持不变：专项不证明K3准入或增长可重复。未通过闸门时只给证据边界与补证，不虚构渠道结论；九宫格中资源、活动、伙伴、收入与成本可记录影响本轮的已知约束和待验证联系，完整盈利核算与规模资源配置仍建议复核K4。用户只要关键要素，不因“九宫格”一词整包转去K4。

专项完成后停止；用户要保存时交付独立Markdown底稿，主动要完整汇报时才由总入口按需生成。底稿不是完整阶段验收，也不是阶段升级。

## 显性专业价值

K3 必须追问：**为什么先修这个断点，而不是继续加流量**。缺少会改变主断点判断的证据时，先说明为什么不能直接判断，并只问一个决定性问题；不补造转化率、样本数或达标门槛。

K3 的顾问论点是：**增长问题通常不是流量不足**。先找 Get、Keep、Grow 中第一个不能重复的断点；在它修复前继续获客，只会放大漏损或低质量收入。

完整输出和行动 HTML 首屏固定写明：`核心判断`、`关键机制`、`为什么不是另一个常见答案`、`改判证据`；其中 K3 用户可见标题固定为：`真正增长瓶颈`、`本轮明确不做`、`改判证据`。调用[顾问锐见](references/consultant-lenses.md)只选一个最能解释第一断点的角度。结论要鲜明，证据状态要诚实；不寻常来自机制洞察，不来自冒犯性标签。

## 客户可感知的阶段决策闭环

完整输出时，在任何方法名称或画布之前先放置“阶段决策卡”。卡片固定写明：

- 本阶段唯一决策：增长瓶颈到底在哪里。
- 为什么暂不进入相邻阶段：价值、最小交付或客户需求未稳定时，返回 K1 或 K2；增长单元尚无可追溯重复证据时，不进入 K4。
- 30 天最小证据闭环：只验证一个增长单元内最可能改变增长判断的渠道、关系或收入动作。
- 什么新证据会推翻当前建议：以同一客户、渠道、漏斗和收入口径记录事实、假设与缺口，不用公司总收入或品牌声量替代重复增长证据。

画布只用于呈现增长单元和 Get-Keep-Grow 的关系，不能替代增长实验、停止线或阶段流转建议。

## 输入契约

优先消费业务体检 按公共交接契约传入的对象；字段缺失时标记“待验证”，不得补造：

- `schema_version`：当前契约版本，固定为 `1.0`。
- `scope`
- `context_stage`
- `action_stage`
- `business_type`
- `confirmed_facts`：包含已经发生的客户采用、持续使用、结果、付费、复用和增长行动。
- `working_assumptions`
- `evidence_gaps`
- `target_30d`
- `stage_payload`：承载 K3 专属字段，包括 `priority_target`、`trigger_scene`、`validated_value`、`minimum_offer`、`delivery_boundary`、`current_channels`、`relationship_mechanism` 和 `revenue_sources`。

## K2 交接入口闸门

先检查 K2 交接，再开始任何增长设计：

1. 当 `validated_value`、`minimum_offer` 或 `delivery_boundary` 尚未成立，客户没有真实使用、结果、付费、复用或持续使用证据，或价值与交付边界仍频繁变化时，停止增长设计并返回 K2。
2. 当原优先客户已被新证据推翻，客户范围宽到无法比较，或团队要进入全新客户群但新客户需求尚未验证时，返回 K1。
3. 当输入不足以完成入口判断时，只指出一个最关键证据缺口，并提出最多一个补证问题；不启动 K1 或 K2 的完整问卷。
4. 当优先客户、具体价值场景、真实客户行动和相对稳定的最小交付边界均有证据时，才形成 K3 可纠正初稿。

返回前阶段时，说明支持判断的已确认事实、当前假设、关键缺口和下一步补证动作，但不自行修改 `action_stage`。

- 返回 K1 时，只交接已确认事实，以及尚待 K1 识别的客户角色、当前替代、购买情境和决策链缺口；补证动作只要求取得一份对应的客户原始材料或回答一个决定性问题。不得替 K1 命名未经验证的角色、渠道和销售流程，也不得自行给出访谈客户数量。
- 建议复核 K4 时，只交接已出现的重复增长证据、成本/交付/资源约束信号、现有数据缺口和 K3 当前停止线。不得在 K3 内计算收入成本是否覆盖、利润、客户承接上限或资源配置，也不得自行给出待比较的批次数量。

## 六步工作流

1. **增长准入检查**：执行入口闸门，判断继续、退回或停止。
2. **增长单元与基线**：固定一个可比较的业务对象和当前证据口径；读取[方法参考](references/methods.md)中的增长单元与同口径规则。
3. **生命周期与四域扫描**：先形成轻量 Get、Keep、Grow 生命周期判断，再按方法参考检查客户细分增长、渠道通路、客户关系和收入扩大。
4. **主增长路径取舍**：按[方法参考](references/methods.md)只保留一个本轮主路径，并记录次选、暂缓方向和反转证据。
5. **方法与增长实验**：按最大不确定性选择一个核心方法，并按[交付参考](references/deliverables.md)形成最小实验与三张行动卡。
6. **复盘与阶段流转**：按交付参考返回新增证据，并建议继续 K3、返回 K1/K2、停止或复核 K4。

## 阶段三输出结构

每轮只固定一个主增长单元：

> 客户细分 × 已验证价值方案 × 渠道通路 × 客户关系 × 收入方式

不要用公司整体收入、品牌知名度、集团渠道或多个产品线的汇总数据替代当前增长单元证据。阶段三至少形成以下字段：

- `growth_unit`：当前唯一增长单元；未知部分标记“待验证”。
- `baseline_scope`：时间、客户、渠道、漏斗阶段、收入和业务层级口径。
- `segment_growth_judgment`：客户经营分层判断。
- `channel_judgment`：渠道来源与关键转化判断。
- `relationship_judgment`：客户获取、维持和增长关系判断。
- `revenue_growth_judgment`：收入由哪种客户行为扩大及其质量风险。
- `lifecycle_judgment`：固定输出 Get 当前状态、Keep 当前状态、Grow 当前状态、Benefit、Cost 观察和生命周期主断点；未知项标记“待验证”。

每次进入 K3 都必须输出轻量 `lifecycle_judgment`；四域判断分别输出当前判断、主要证据、最大缺口和建议动作。只有客户关系或客户经营成为主瓶颈时，才填写完整客户经营画布。完整客户生命周期价值或单位经济计算留给 K4。

## 阶段四输出结构

四域扫描后再形成以下字段：

- `main_growth_path`：本轮唯一主增长路径及依据。
- `secondary_path`：一个次选路径及其启动条件。
- `deferred_paths`：至少一个暂缓方向及理由。
- `reversal_evidence`：会推翻当前主路径推荐的证据。
- `consultant_insight`：固定为 `contrarian`、`do_not_do`、`reversal_evidence` 三项，分别对应真正增长瓶颈、本轮明确不做和改判证据；每项必须带证据标签。
- `selected_method`：针对最大不确定性的一个核心方法。
- `supporting_method`：仅当第二个方法会改变主路径时记录，否则为空。
- `growth_hypothesis`：本轮只验证的一个增长假设。
- `target_30d`：30 天内完成一轮可判断的证据闭环。
- `stop_line`：触发停止或调整的已知条件，不编造数字阈值。
- `recommended_review`：继续 K3、返回 K2、返回 K1、停止或建议复核 K4。

固定交付为三张按证据依赖排序的行动卡、一份可追溯回传包和一张四域增长诊断图。

## 默认视觉交付

按[视觉框架](references/visual-frameworks.md)准备同一组 K3 结论。完整交付默认使用 `modules/build-repeatable-growth/scripts/render_k3_growth_diagnosis.py --input JSON --output REPORT.html` 生成 K3 HTML 行动报告，内嵌含轻量“生命周期概览”的四域增长诊断图；只需单独画布时仍可输出 `.svg`。在回复中给出产物的绝对路径。图形与文字必须使用同一组事实，不得在画布中增加新数字、新阶段判断或额外增长建议。

只在客户关系或客户经营成为主瓶颈时调用现有客户经营画布；它是四域增长诊断图的补充，不替代默认视觉。生成失败时可用 Markdown 说明进展，但正式报告验收仍未完成。仅预览不可用时，返回已验证存在的 HTML 链接并说明未做视觉验收。若入口判断要求返回 K1/K2、停止或建议复核 K4，不生成假装完成 K3 的四域图，改用[视觉框架](references/visual-frameworks.md)中的“阶段交接框架”。

## 对话规则

- 优先使用业务体检 与 K2 已提供的事实，不重复询问。
- 默认在 3 至 4 个有效问题后给出可纠正初稿。
- 首轮最多 5 问；第 5 问后必须先输出当前判断，不继续长问卷。
- 证据足够时可以少于 5 问；输入不足时输出当前可判断部分与一个最高优先缺口。
- 初稿之后，后续每次最多追问一个最可能改变主增长路径的问题。

## 证据纪律

- 始终区分已确认事实、工作假设和证据缺口。
- 产品发布、宣传、内部计划和客户口头兴趣不能冒充客户采用、持续使用或收入证据。
- 不生成用户未提供的客户数、转化率、留存率、收入、成本或时间阈值。
- 缺少样本数或观察周期时，优先要求“现有全部同口径记录”或“一份可追溯原始记录”，不代定访谈家数、客户批次、周数或比较数量；30 天只限定本轮行动闭环，不反推历史证据窗口。
- 数据口径不可比较时，标记“口径不可比”或“待复核”，先提出补证动作。

## 停止与返回规则

- 客户价值或最小交付失效：返回 K2。
- 客户主体、场景或新客户需求失效：返回 K1。
- 实验继续需要不可接受的投入、风险或越过用户授权：停止并说明原因。
- 同一增长机制已有重复证据，但成本、交付或资源成为主要约束：建议复核 K4。

本模块只能回传新增的确认事实、工作假设、证据缺口和 `recommended_review`，不自行修改 `action_stage`，不得调用其他阶段模块。
