# K4 可视化输出规范

## 目标与取舍

完整交付默认生成 K4 HTML 行动报告并内嵌一张“K4 经营模型与资源优化图”；单独画布可输出 SVG。将商业模式、收入成本、资源约束和经营杠杆放在同一证据链上。不要机械重画九宫格，也不要生成相互矛盾的多张图；用户明确要求分图时，才从同一组结论拆分。

## 固定结构

一张图按以下顺序呈现：

1. 诊断口径、本轮取舍和证据状态。
2. **商业模式与经营结果链**：客户与价值、收入机制、交付与资源、经营结果。
3. **经营单元拆分**：成熟主业与新业务或新品类分别呈现，不用公司总利润混算。
4. **收入成本判断**：`data_readiness`、`comparison_result` 和 `main_constraint`。
5. **资源约束**：`resource_constraint` 与其优先原因。
6. **商业模式重构复核**：只能使用阶段5的三种状态，不在图中自行判定 S7。
7. **最多三个经营杠杆**：每项都显示机制、代价与停止或调整条件。
8. **30 天优先验证**和停止线。

## 证据和展示边界

- 图文使用同一组事实；图中结论必须来自阶段2至5已有字段，不能为了“好看”补利润、占比、回收期或行业阈值。
- 已确认事实、工作假设和证据缺口至少在内容或证据摘要中显式区分。
- `operating_scope_split` 无法区分成熟主业与新业务或新品类时，不生成完整经营优化图，改为补证交接框架。
- `operating_levers` 只允许一至三个。没有合格杠杆时停在诊断结论，不生成空行动图。
- To C 的经营单位可以是同一产品、服务、渠道与客户周期；To B 可以是同一合同、客户账户、解决方案或续约周期，但必须与文字结论一致。

## 生成与降级

将同一组结构化字段写入 UTF-8 JSON，然后运行：

```bash
python skills/optimize-business-model-and-resources/scripts/render_k4_operating_model.py --input /absolute/path/k4.json --output /absolute/path/k4-operating-model.html
```

完整交付默认输出 HTML，并使用绝对路径返回给用户；单独画布输出 SVG。若无法写文件或渲染失败，可用 Markdown 按“经营结果链—经营单元拆分—收入成本—资源约束—经营杠杆—30 天验证—停止线”说明进展，但不算正式报告验收完成。仅预览不可用时保留已验证存在的 HTML 交付并说明未做视觉验收。
