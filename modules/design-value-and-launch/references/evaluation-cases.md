# K2 完整交付评测案例

以下内容均为测试输入，不是客户事实，不得复制到真实交付中。

## Case A：宽泛 To B 客群

输入：“我们想为中小企业做一个 AI 经营平台，客户都需要降本增效。”

期望：返回 K1。原因是“中小企业”不可直接识别和验证，且没有具体场景、客户任务、当前替代或已发生行动。只问一个问题，例如：“哪一类企业中的哪个角色，最近在什么具体任务上已经主动寻找或拼凑解决办法？”

禁止：直接设计 AI 平台功能，或把“降本增效”当作已确认价值缺口。

## Case B：证据足够进入 K2

输入：某区域连锁的财务负责人每周汇总门店经营数据，当前用 Excel 与微信群反复催收、核对；对方已提供一份脱敏样表并参加共创会议。尚不确定其最在意的是汇总耗时、错漏风险还是追责困难。

期望：可以进入 K2，并形成带证据边界的价值缺口初稿。已提供脱敏样表和参加共创是已确认行动；哪个结果最重要仍是工作假设和证据缺口。若继续形成候选价值主张，必须保留该证据缺口，不得直接跳到完整系统方案。

## Case C：混合角色未拆分

输入：企业采购者希望控制成本，部门使用者希望减少操作步骤，团队把两者写成同一个“企业客户价值主张”，但没有确认谁获得价值、谁使用、谁决策和谁付费。

期望：返回 K1，先拆分角色与各自场景；只追问最影响判断的一个角色问题。不得把采购目标和使用任务拼成一个价值缺口。

## Case D：To B 采购与使用价值分离

输入：部门使用者喜欢演示中的自动汇总，但采购者关注数据合规、预算和供应商责任，交付团队尚未核实部署与培训成本。

期望：分别记录使用者、业务负责人、决策/采购者和交付方；不得用使用者好评证明采购价值，也不得把签约视为采用成功。最小价值单元只覆盖一次可控交付和可观察结果。

## Case E：To C 短标签保持

输入：K1 已将优先客群规范短标签确定为“二胎副业宝妈”，K2 又获得晚间选品场景和本人付费证据。

期望：所有对外客户名称继续原样使用“二胎副业宝妈”，不得追加场景、行为或角色后缀；晚间选品、使用者与付费者关系进入证据字段。

## Case F：混合业务一侧有证据

输入：渠道已确认愿意采购并安排门店部署，但尚未观察最终个人用户是否开始、完成或持续使用。

期望：分别输出企业/渠道价值路径和最终个人用户价值路径；渠道证据不能证明个人用户价值，个人用户侧标为待验证。

## Case G：技术团队过早建设后台

输入：团队希望先建设完整 CRM、数据仓库、复杂权限和自动化工作流，但当前只需完成一次预约、人工交付、结果确认和异常记录。

期望：后台只保留记录、责任人、关键交付节点、结果与证据、异常处理；优先使用人工服务、表单或简单工具，并把完整平台列入排除范围。

## Case H：口头认可但没有真实行动

输入：五位受访者都说方案“很好、愿意试试”，但没有人提交真实材料、安排实际使用或投入任何时间和资源。

期望：识别为需求风险或采用风险，不能把口头认可写成价值成立。风险试点只选择一个前置假设，并要求一种与真实场景相连的客户行为。

## Case I：单一客户结果依赖创始人

输入：一位客户在创始人全程陪同和额外定制下获得结果，普通交付团队尚未复现。

期望：识别交付风险并保持 K2；该结果不能证明最小交付已经稳定，也不能建议直接进入可重复增长。

## Case J：采购付费但最终用户未采用

输入：渠道已经采购并付费，但最终个人用户没有开始或完成关键动作。

期望：采购承诺只支持企业/渠道路径，采购付费不能替代使用者采用证据；最终个人用户价值路径仍为待验证，两侧不共享未经验证的价值证据。

## Case K：没有历史基线

输入：团队希望把“10 位客户、转化率 30%、两周内完成”直接写成成功标准，但客户没有历史数据，也未共同确认这些门槛。

期望：先建立同口径基线，不自行设定客户数、转化率、收入或时间门槛；先用真实行为、结果是否出现及相对变化形成可纠正判断。

## Case L：画布与正文使用不同事实

输入：七段正文把优先客户写为区域连锁财务负责人，核心画布却写成门店店长；正文将汇总耗时列为待验证，画布则写成“效率提升 50%”。

期望：判定交付不合格。核心画布必须与七段结果使用同一组事实，未知效果标记“待验证”；不得补造客户、效果或经营数据。

## Case M：堆叠多张辅助画布

输入：团队希望同时展示创新竞争图、创新决策矩阵、风险假设画布、客户旅程图和同理心地图，以显得分析完整。

期望：默认只交付一张核心画布，根据最大不确定性最多增加一张对外辅助画布；其余工具即使参与内部判断，也不得同时对外展示。

## Case N：行动卡变成平台路线图

输入：三张行动卡分别是建设完整 CRM、建设数据仓库和开发复杂权限平台，但当前只需要验证一次客户提交、人工交付和结果确认。

期望：重写为按证据依赖排序的三张最小行动卡，只服务同一轮价值证据闭环；完整系统进入排除范围。

## Case O：补造 30 天门槛

输入：没有历史基线或用户明确标准，团队把“30 天获得 100 位客户、转化率达到 30%、收入达到 10 万元”写成成功条件。

期望：删除补造阈值。具体数量、周期和阈值只能来自客户历史基线、当前资源约束或用户明确标准；否则标记“待验证”。

## Case P：特殊客户成功误升 K3

输入：一位客户在创始人全程陪同和大量额外定制下完成使用并付费，团队希望直接宣布进入 K3 可重复增长。

期望：保持 K2 或建议诊断层复核。该结果可进入 K2 回传证据包，但不可证明普通交付可复制；Skill 不自行升级阶段。

## Case Q：只给文字画布

输入：K2 七段结果、优先价值主张和最小价值闭环已完整，但结果只输出长段文字和 Markdown 表格，没有生成或显示 SVG。

期望：判定视觉交付未完成。默认调用 `render_k2_value_canvas.py` 生成并显示一张核心画布；只有环境无法生成或显示 SVG 时，才降级为紧凑 Markdown 画布并披露原因。图文使用同一组事实，不得为填满画布补造数据。

## 评测边界

本轮测试入口、返回 K1、价值缺口、价值主张取舍、最小价值单元、业务分流、单一风险试点、七段结果、三张行动卡、30 天目标、回传包、核心 SVG 画布和辅助画布路由。仍不测试完整定价、单位经济模型、产品路线图、所有辅助工具的独立渲染器或 K3 增长设计。
