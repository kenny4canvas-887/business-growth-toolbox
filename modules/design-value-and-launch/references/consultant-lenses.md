# K2 顾问判断视角

每次最多选择一个最能改变本轮价值设计的视角。证据不足时，不叠加观点，只问一个最可能改变判断的问题。每个观点都必须标记 `[已确认]`、`[假设]` 或 `[缺口]`，并写明改判证据。

## 视角一：客户购买的是改变，不是功能

- **适用证据**：客户提出功能、演示反馈很多，但真实使用或结果证据很少。
- **核心判断**：客户愿意改变现有做法，才说明价值可能成立；功能被认可不等于改变已经发生。
- **拒绝的常见答案**：“客户喜欢这个功能，所以价值已经验证。”
- **最贵误判**：把产品兴趣当成采用意愿，继续增加客户不会使用的功能。
- **本轮选择**：锁定一个客户必须完成的关键动作，以及动作后可观察的结果。
- **改判证据**：客户在真实场景持续完成关键动作，且结果优于现有替代。

## 视角二：真正竞争者常是维持现状

- **适用证据**：客户知道问题，也比较过方案，但一直没有行动。
- **核心判断**：K2 的首要竞争者可能不是同类产品，而是人工处理、延后处理或容忍损失。
- **拒绝的常见答案**：“只要比竞品功能更强，客户就会切换。”
- **最贵误判**：低估切换成本，把没有预算、没有负责人或没有紧迫性误写成产品差异不足。
- **本轮选择**：比较新方案与维持现状的完整成本、风险和麻烦，而不只比较功能。
- **改判证据**：客户已经为解决问题调配预算、负责人或明确时间窗口。

## 视角三：最小价值单元不是最小功能集

- **适用证据**：团队已列出 MVP 功能，但客户能否完成一次完整任务仍不清楚。
- **核心判断**：最小价值单元必须交付一个完整客户结果；删到无法完成任务的版本只是残缺产品。
- **拒绝的常见答案**：“先上线最少几个功能，看有没有人点。”
- **最贵误判**：用点击和试用掩盖客户没有获得结果，得到无法支持下一步投入的假阳性。
- **本轮选择**：从入口到结果确认保留完整闭环，其余功能明确排除。
- **改判证据**：客户无需额外人工补救即可完成关键任务，并留下可追溯结果。

## 视角四：使用通过不等于购买链通过

- **适用证据**：To B 或混合业务中，使用者、负责人、采购者和付费者不是同一角色。
- **核心判断**：单一角色满意只能证明局部价值；采用、审批、交付和付费必须分别识别阻力。
- **拒绝的常见答案**：“一线用户喜欢，企业自然会采购。”
- **最贵误判**：把试用成功当成商业闭环，直到采购或交付阶段才发现价值无法兑现。
- **本轮选择**：只验证当前最可能阻断价值兑现的一个角色及其关键动作。
- **改判证据**：关键角色完成与其职责匹配的真实承诺，且下一角色的交接可追溯。

## 视角五：单次惊艳不等于价值机制成立

- **适用证据**：一个客户在创始人陪同、额外定制或特殊资源下获得了好结果。
- **核心判断**：单次成功只能证明“在这些特殊条件下可行”，不能证明稳定价值机制已经成立。
- **拒绝的常见答案**：“首个案例效果很好，可以立即复制。”
- **最贵误判**：把不可重复的英雄式交付写成产品能力，过早进入 K3 扩量。
- **本轮选择**：公开列出本次成功依赖的特殊条件，并测试能否删掉其中一个。
- **改判证据**：不同客户在预设交付边界内仍完成相同关键动作并获得同类结果。
