# K2 入口、价值主张、最小价值单元与风险试点方法

本轮开放模块一至模块四。方法负责检查 K1 交接、诊断价值缺口、取舍价值主张，把优先方案压缩为最小价值单元，并设计一个最高风险试点。

## 1. 入口检查

按以下顺序判断，不用总分掩盖关键缺口：

1. **客户是否具体**：能够识别、触达和验证，而不是人口大类或企业规模大类。
2. **具体场景是否存在**：知道问题在什么事件、时间或经营情境出现。
3. **客户任务是否明确**：知道客户必须完成什么，或必须获得什么结果。
4. **当前替代方式是否可描述**：包括产品、服务、人工流程、拼凑方案或暂不处理。
5. **行动是否超过口头兴趣**：至少观察到比较、提交材料、会议、试用、共创、预算、采购或付费等一种已发生行动；否则标为进入后续模块前必须补齐的证据风险。

任何关键项不清楚时，优先提出一个会改变判断的问题。不要用一轮长问卷同时补齐全部字段。

## 2. 价值缺口链

价值缺口链为：

```text
具体场景 → 客户任务 → 当前替代方式 → 可观察缺口
```

逐项判断：

| 环节 | 判断问题 | 不能接受的替代答案 |
| --- | --- | --- |
| 具体场景 | 问题在什么事件、时间或经营情境发生？ | “日常”“数字化转型”等空泛背景 |
| 客户任务 | 客户当时必须完成什么或获得什么结果？ | 团队希望客户使用什么功能 |
| 当前替代方式 | 客户现在如何解决或为什么暂不处理？ | 只列竞品，不描述实际行为 |
| 延续原因 | 客户为什么仍然使用现有方式？ | 把团队猜测写成客户原因 |
| 结果损失 | 现有方式造成什么成本、延误、风险、麻烦或结果损失？ | 无基线的夸张金额或比例 |
| 期望改变 | 客户希望获得什么可观察的改变？ | “体验更好”“更智能”等口号 |

## 3. 判断不行动与采用阻力

区分四类原因，因为它们会导向完全不同的价值判断：

- **问题不重要**：客户可以长期搁置，价值主张可能没有成立基础。
- **预期收益不足**：客户看见问题，但认为改变带来的结果不值得。
- **使用惰性**：旧流程虽不理想，却熟悉、兼容或迁移成本低。
- **购买或采用顾虑**：客户担心预算、审批、风险、学习或责任承担。

不要把“不采用”一律解释为客户不了解产品。

## 4. 证据分层

- 已发生且可追溯的客户行为写入已确认事实。
- 对行为原因、问题严重度和期望结果的解释写入工作假设。
- 可能推翻目标客户、任务、替代方式或缺口的未知项写入证据缺口。

最终只选择一个主要价值缺口。若两个缺口服务不同角色、不同场景或不同任务，先拆分，不将其拼成一个价值主张。

## 5. 形成候选价值主张

价值缺口成立后，默认形成 2 至 3 个候选价值主张。只有证据明确指向唯一方案时，才允许只保留一个；“团队只想到一种方案”不属于唯一证据。

每个候选必须写清：

- 目标客户。
- 具体场景。
- 客户任务或改变。
- 核心价值机制，即为什么可能带来结果，而不是功能清单。
- 相对现有替代的改善。
- 支持它的已确认事实、工作假设和证据缺口。

统一使用以下句式形成可比较初稿：

> 帮助【目标客户】在【具体场景】完成【客户任务或改变】，通过【核心价值机制】减少或避免【现有替代的关键缺口】。

候选之间应改变价值机制、结果路径或关键取舍，不能只替换形容词。

## 6. 六维定性取舍

逐项比较候选，不用总分掩盖关键风险：

| 维度 | 判断问题 |
| --- | --- |
| 问题重要性 | 这个缺口是否值得客户采取行动？ |
| 结果可感知性 | 客户能否在合理时间内观察到改变？ |
| 差异性 | 相对现有替代是否有清晰且相关的改善？ |
| 可交付性 | 团队能否以当前能力兑现核心价值？ |
| 可验证性 | 能否用小范围行动获得决定性证据？ |
| 风险 | 是否存在信任、合规、迁移、成本或采用障碍？ |

没有客户基线时只使用“较强、一般、较弱、待验证”，不生成数学总分，也不把内部偏好伪装成精确评分。

最终只选择一个优先价值主张，同时保留暂不选择的候选和舍弃理由。舍弃理由应指向证据、约束或关键维度，不写“感觉较弱”。

## 7. 最小价值单元

最小价值单元不是最少功能，而是一次最小但完整的价值闭环：客户能够完成关键任务并获得可观察结果，团队能够记录足以支持、修正或推翻价值主张的决定性证据。

必须包含六项：

1. **客户入口**：客户在什么触发下从哪里开始。
2. **客户核心动作**：客户必须亲自完成的关键行为。
3. **产品或服务支持**：团队为完成该动作提供的最少支持。
4. **可观察结果**：客户和团队如何看见任务是否完成或结果是否改善。
5. **团队记录证据**：记录哪项行为、结果、阻力或异常来改变后续判断。
6. **排除范围**：本轮明确不做的功能、角色、场景、集成和自动化。

若缺少任何一项，就还不是可验证的完整价值单元。排除范围不能写成“其他以后再说”，必须列出最容易诱发过度建设的内容。

## 8. 前后台最短闭环

产品端只设计四步：

```text
进入/提交 → 核心动作 → 交付/反馈 → 结果确认
```

后台端只保留五项：

1. 线索、预约或订单记录。
2. 责任人。
3. 关键交付节点。
4. 结果与证据。
5. 异常处理。

能用人工服务、表单、样品、演示或简单工具验证时，默认先用这些方式，不提前建设完整系统、CRM、数据仓库、复杂权限或全自动流程。只有缺少某项能力会阻断客户获得核心价值或阻断决定性证据时，才把它纳入本轮。

## 9. 按业务类型分流

### To B

分别判断：

- **使用者**：能否完成任务、是否愿意持续使用、学习和迁移阻力是什么。
- **业务负责人**：能否获得可观察业务结果，是否愿意承担采用责任。
- **决策/采购者**：审批价值、预算、风险、合规和替代方案标准是什么。
- **交付方**：部署、培训、集成、服务成本和持续支持是否可控。

必须保留两个判断边界：使用者喜欢不等于采购批准；采购完成不等于采用成功。

### To C

对外客户名称原样复用 K1 的不超过 10 个汉字的规范短标签，不得追加场景、行为或角色后缀。内部仍需判断触发场景、即时或持续结果、替代原因、信任与学习阻力、价格和持续采用，以及使用者、决策者、付费者是否为同一人。

### 混合业务

分别形成两条完整路径：

- 企业/渠道价值路径：购买、部署、采用和续用。
- 最终个人用户价值路径：开始、完成和持续使用。

两条路径可以共享已经确认的产品与交付事实，但不共享未经验证的价值证据。一侧成立不能自动证明另一侧成立。

## 10. 风险分类

只判断会影响当前优先价值主张和最小价值单元的风险：

- **需求风险**：客户是否真的重视该问题并愿意采取行动。
- **价值风险**：产品或服务是否带来客户在意的改变。
- **采用风险**：客户是否愿意开始、完成并继续使用。
- **交付风险**：团队能否在承诺边界内稳定兑现。
- **付费风险**：购买者是否愿意为已获得或预期价值承担成本。

付费可以作为价值证据，但不展开完整定价体系或单位经济模型。To B 和混合业务中，采购付费不能替代使用者采用证据，渠道承诺也不能替代最终个人用户的结果证据。

## 11. 选择一个最高风险假设

每轮只选择一个同时满足以下条件的假设：

1. **最可能推翻当前价值主张**：若不成立，当前价值机制或最小价值单元需要实质调整。
2. **能够低成本验证**：可用一次最小客户行为和可追溯结果证据判断，不需要先建设完整系统。

优先选择最接近当前证据断点的风险，不因团队更容易测试而回避更可能推翻方案的风险。两个风险同样关键时，先验证前置风险；例如需求尚未成立时，不先验证定价偏好。

## 12. 最小风险试点

试点只覆盖一个假设，并固定写清：验证对象、当前假设、最小测试方式、客户必须完成的真实行为、团队记录的结果证据，以及继续、调整和停止条件。

客户真实行为必须超过口头赞同，例如提交真实材料、完成关键步骤、投入时间或资源、实际使用、确认结果、预算或付费。具体采用哪一种取决于当前风险，不把任一行为预设为所有项目的统一门槛。

没有历史基线时，先建立同口径基线，再比较试点前后；不自行设定客户数、转化率、收入或时间门槛。用户未提供阈值时，条件使用可观察行为、相对变化和证据是否出现来表达，并标记仍待共同确认的业务阈值。

## 13. 证据等级

按证据实际证明的内容记录，不把证据串成自动升级阶梯：

1. **表达**：客户明确描述问题、任务、替代方式或期望结果。
2. **投入**：客户投入材料、数据、时间、人员或预算准备。
3. **使用**：客户开始并完成关键动作，或持续使用。
4. **结果**：出现客户在意且可观察的行为或业务改变。
5. **承诺**：客户作出预算、采购、付费、续用或扩大范围等承诺。

较强等级不自动证明其他等级：愿意投入试点不证明结果已经出现，采购付费不证明使用者采用，单次结果也不证明能够稳定交付。

## 14. 试点后的阶段闸门

- **保持 K2**：价值主张尚未被结果证明；只有意愿而没有关键行动或结果；结果依赖特殊人员、资源或不可重复条件；使用者喜欢但购买者不认可。
- **调整 K2**：问题成立，但价值机制、表达、交付边界或采用方式没有产生预期证据。
- **停止**：重复验证仍不改变客户行为或结果，客户持续选择原替代方式，也没有更强承诺。
- **返回 K1**：新证据推翻优先目标客户、场景或客户问题定位假设。
- **建议复核 K3**：已经出现实际使用、结果、付费或持续使用证据，且最小交付边界开始稳定；单一特殊客户成功不等于可重复增长渠道。

本 Skill 只返回证据与阶段建议，不得自行升级阶段。
