# K2 价值设计画布与辅助框架

## 默认核心画布

入口通过后默认交付一张“价值设计画布（K2 价值主张设计）”。画布必须已填写，不得展示空白模板；每一格都必须标注为已确认事实、工作假设或证据缺口，未知内容写“待验证”。

| 模块 | 填写规则 |
| --- | --- |
| 目标客户 | 原样复用 K1 的一个优先 Target；To C 继续使用不超过 10 个汉字的规范短标签。 |
| 场景与任务 | 写出触发事件、客户必须完成的任务和角色关系，不把产品功能当任务。 |
| 痛点与好结果 | 写出现有替代造成的可观察缺口，以及客户希望出现但尚需证据验证的结果。 |
| 产品或服务载体 | 只写完成一次最小价值单元所需的产品、人工服务或简单工具。 |
| 痛点缓解 | 说明载体如何减少具体损失、阻力或不确定性；效果未知时标记“待验证”。 |
| 收益创造 | 说明客户可能获得的可观察改变，不补造时间、收入或转化结果。 |
| 价值匹配证据 | 分列已发生的客户行为、结果证据、继续或付费承诺，以及仍缺失的反证。 |

核心画布必须与七段结果使用同一组事实。可先用价值缺口链校验客户侧：

```text
场景 → 任务 → 当前替代 → 可观察缺口
```

再用最小价值单元链校验供给侧：

```text
客户入口 → 客户核心动作 → 产品或服务支持 → 可观察结果 → 团队记录证据
```

链条下方单列排除范围。产品端只用“进入/提交 → 核心动作 → 交付/反馈 → 结果确认”四步；后台端只列记录、责任人、关键交付节点、结果与证据、异常处理五项。

混合业务应把企业/渠道价值路径与最终个人用户价值路径并列展示，并在两条路径之间标明“只共享已确认产品事实，不共享未经验证的价值证据”。

## 生成并显示核心画布

完整交付默认生成并显示一张 K2 HTML 行动报告页面并内嵌核心画布，不只给文字画布；单独画布可输出 SVG。先将已形成的 K2 结论写入 UTF-8 JSON，不为了填满画布新增事实。

JSON 包含 `title`、`stage`、`decision`、`value_proposition`、`sections`、`minimum_value_flow`、`exclusions` 和 `stop_line`。`sections` 必须恰好包含 `target`、`scene_job`、`pain_outcome`、`offering`、`pain_relief`、`gain_creation` 和 `evidence` 七格。`value_proposition` 及七格每条内容必须以 `[已确认]`、`[假设]` 或 `[缺口]` 开头。`minimum_value_flow` 是恰好包含五项的字符串数组，依次写入客户入口、客户核心动作、产品或服务支持、可观察结果和团队记录证据；`exclusions` 和 `stop_line` 均为非空字符串数组。

将输入和输出保存到可写的工作区或临时目录，再使用绝对路径运行：

```bash
python3 /absolute/path/to/design-value-and-launch/scripts/render_k2_value_canvas.py --input /absolute/path/to/k2-value.json --output /absolute/path/to/k2-value.html
```

生成后返回 HTML 的绝对路径链接；单独画布才显示 SVG。若脚本拒绝输入，先修正缺失字段或证据标签，不绕过校验。生成失败可用 Markdown 说明进展，保留相同七格、证据标签、最小价值闭环、排除范围和停止线，但不算正式报告验收完成。仅预览不可用时保留 HTML 交付并说明未做视觉验收。

## 最多一张辅助画布

最多增加一张辅助画布，并根据当前最大不确定性选择对外框架：

| 最大不确定性 | 选择的辅助画布 |
| --- | --- |
| 不知道客户为什么不行动 | 创新竞争图 |
| 多种价值方案难以取舍 | 创新决策矩阵 |
| 不知道先验证哪个假设 | 风险假设画布 |
| 使用过程和关键触点不清 | 客户旅程图 |
| 客户情绪、顾虑和行为证据不足 | 同理心地图 |

创新竞争图和创新决策矩阵可同时作为内部判断过程，但对外只能选择其中一张；另一工具仅作为内部判断过程，不得让工具数量替代取舍结论。

创新决策矩阵按下表填写实际候选和证据判断：

| 候选价值主张 | 问题重要性 | 结果可感知性 | 差异性 | 可交付性 | 可验证性 | 风险 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 候选 A | 较强/一般/较弱/待验证 | 同左 | 同左 | 同左 | 同左 | 同左 | 优先/暂不选择 |
| 候选 B | 较强/一般/较弱/待验证 | 同左 | 同左 | 同左 | 同左 | 同左 | 优先/暂不选择 |

模块四的内部风险判定链为：

```text
最高风险假设 → 最小测试 → 客户真实行为 → 结果证据 → 继续/调整/停止
```

若风险假设是最大不确定性，可把这条链扩展为唯一一张对外风险假设画布；否则只作内部检查。

## 客户经营画布边界

客户经营画布不是默认 K2 画布。只有已经出现交付、使用或维护行为，且当前问题是价值如何被持续实现时，才可将其选为辅助画布；它仍占用“最多一张辅助画布”的名额。若核心问题只是客户是否需要、是否采用或价值主张如何取舍，不使用客户经营画布。

核心 SVG 和七段文字必须由同一组 K2 字段生成。辅助画布可用紧凑图表或 Markdown 框架展示，但仍只能选一张；不为每个辅助工具新建独立渲染器。
