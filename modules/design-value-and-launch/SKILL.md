# K2 做最小方案（design-value-and-launch）

> 这是 BMI 业务增长工具箱的八个阶段模块之一，回答「最小价值能否被真实使用并产生结果」。
> 前置：只有根 `SKILL.md`（业务体检）已确认 `action_stage=K2` 时，才由它加载本模块。本模块不重新诊断阶段，不自行修改 `action_stage`，不调用其他阶段模块。
> 收口：验证闭环后回传业务体检，复核是否进入 K3。

## 概述

把 K1 交接的优先客户、具体场景和客户问题转化为有证据边界的价值缺口，形成并取舍候选价值主张，再压缩成能完成客户任务并获得决定性证据的最小价值单元。最终交付七段完整 K2 结果、一张已填写的核心画布、最多一张辅助画布、三张行动卡、30 天价值验证目标和可追溯的 K2 回传证据包。

## 显性专业价值

K2 必须追问：**客户最少完成什么动作才算获得价值**。缺少会改变最小价值闭环判断的证据时，先说明为什么不能直接判断，并只问一个决定性问题；不把功能数量当成客户价值。

K2 的顾问论点是：**价值不是功能更多，而是客户有足够理由改变现有做法**。价值成立意味着目标客户愿意承受切换成本，并以更低的时间、金钱、风险或认知成本完成关键任务；否则先删减交付，不用功能堆叠掩盖价值缺口。

完整输出和行动 HTML 首屏固定写明：`核心判断`、`关键机制`、`为什么不是另一个常见答案`、`改判证据`。结论要鲜明，证据状态要诚实；不寻常来自机制洞察，不来自冒犯性标签。

每轮从 [顾问判断视角](modules/design-value-and-launch/references/consultant-lenses.md) 中最多选择一个最能改变本轮决策的视角，明确写出“客户为何改变”“本轮明确删掉”和“改判证据”。不得把五个视角全部堆进报告，也不得用锐利措辞替代证据。

## 客户可感知的阶段决策闭环

完整输出时，在任何方法名称或画布之前先放置“阶段决策卡”。卡片固定写明：

- 本阶段唯一决策：最小价值闭环是否成立。
- 为什么暂不进入相邻阶段：价值缺口、最小交付或真实采用证据仍未成立时，不进入 K3；目标客户或问题被推翻时，返回 K1。
- 30 天最小证据闭环：只验证最可能推翻优先价值主张的一项最高风险假设。
- 什么新证据会推翻当前建议：区分客户已发生行动、工作假设和待补证信息，不用功能清单、内部设想或画布完成度替代价值证据。

画布只用于说明客户任务、替代与价值取舍，不能替代最低可行启动、行动卡或阶段回退。

## 执行约定

用户明确请求优先于默认流程与展示偏好。复用交接证据；完整分析或正式测试已授权本轮分析和本地报告，不逐步重复确认。证据闸门仍须满足，发布、部署和全局同步须另获授权。若本模块规则导致暂停或偏离请求，链接具体规则并说明原因。

## 输入契约

优先接收诊断层按公共交接契约传入的对象：

- `schema_version`：当前契约版本，固定为 `1.0`。
- `scope`：当前业务或项目范围。
- `context_stage`：企业或主业务的背景阶段。
- `action_stage`：当前行动阶段，期望为 K2。
- `business_type`：To B、To C 或混合业务。
- `confirmed_facts`：已确认事实；客户已经发生的比较、材料、会议、试用、共创、预算、采购或付费等行动也归入此字段。
- `working_assumptions`：当前合理但尚未被行动证明的解释。
- `evidence_gaps`：会改变目标客户或问题判断的缺失证据。
- `target_30d`：本轮 30 天内要形成的最小证据闭环。
- `stage_payload`：承载 K2 专属字段，包括 `priority_target`、`trigger_scene`、`customer_job`、`customer_problem_hypothesis`、`current_alternative` 和 `non_target`。

字段缺失时标记“待验证”，不得为补齐字段而编造事实。

## 工作流

### 1. 确认阶段与业务类型

只有 `action_stage=K2` 时才执行本模块。先确认是 To B、To C 还是混合业务；混合业务若尚未拆清价值获得者、使用者、决策者和付费者，不把他们合成一个客户。

### 2. 执行入口闸门

同时满足以下条件时，可以进入 K2 并形成可纠正初稿：

- 已有一个具体的 `priority_target`，不是“中产”“年轻人”“中小企业”等宽泛群体。
- 已有一个具体 `trigger_scene`。
- 已知 `customer_job`、问题或未满足结果。
- 已知一种 `current_alternative`，或明确把它作为当前最大证据缺口。
- `confirmed_facts` 中至少有一项比口头兴趣更强的客户行动；若尚无，必须把行动证据列为进入后续价值设计前必须补齐的风险，此时只形成带证据风险的价值缺口初稿。

出现以下任一情况时返回 K1：

- 目标客户过宽，无法识别、触达或验证。
- 只有产品想法，没有具体场景和客户任务。
- 问题只来自内部推测，没有现实替代行为或行动线索。
- 多类客户、角色或问题被混在同一价值主张中。
- 新证据推翻了优先 Target 或客户问题定位假设。

返回 K1 时只给出最关键的缺失证据和最多一个补证问题，不重新执行整套 K1 问卷。

### 3. 诊断价值缺口

入口通过后读取方法参考，只从客户场景、任务、当前替代与结果损失诊断价值缺口，不从内部功能清单反推价值。

把每项信息标成：

- `已确认事实`：用户提供的已发生、可追溯信息。
- `工作假设`：当前合理但尚未被行动证明的解释。
- `证据缺口`：会改变价值缺口判断的缺失信息。

默认在 3-4 个有效问题后给出可纠正初稿；首轮总提问最多 5 个。一次只问一个最能改变入口或价值缺口判断的问题。

### 4. 设计并取舍价值主张

只有价值缺口成立时才进入模块二。默认形成 2 至 3 个候选价值主张；只有证据明确指向唯一方案时，才允许只保留一个候选。

每个候选必须包含目标客户、具体场景、客户任务或改变、核心价值机制、相对现有替代的改善，以及对应的已确认事实、工作假设和证据缺口。按方法参考的六个维度做定性比较，只选择一个优先价值主张，同时保留暂不选择的方案及舍弃理由。

### 5. 定义最小价值单元与最小交付

把优先价值主张压缩成一个最小价值单元：客户能够完成一次关键任务、获得一个可观察结果，团队也获得能改变后续判断的证据。必须写明客户入口、客户核心动作、产品或服务支持、可观察结果、团队记录证据和排除范围。

按 `business_type` 分流：

- To B：分别判断使用者、业务负责人、决策/采购者和交付方的任务、结果、采用阻力与证据。
- To C：原样复用 K1 的不超过 10 个汉字的规范短标签，不得追加场景、行为或角色后缀；完整场景和角色只进入证据字段。
- 混合业务：分别形成企业/渠道价值路径和最终个人用户价值路径，两侧可以共享产品事实，但不共享未经验证的价值证据。

### 6. 设计单一最高风险试点

只有优先价值主张和最小价值单元都已形成时才进入模块四。每轮只选择一个最可能推翻当前价值主张、且能够低成本验证的最高风险假设，不把多个风险拼成一轮综合试点。

按方法参考判断风险类型和证据等级，再输出一份风险试点卡。没有历史基线时先建立同口径基线，不自行设定客户数、转化率、收入或时间门槛。To B 和混合业务必须按角色与价值路径记录证据，不能用采购、付费或渠道承诺替代最终使用者的采用与结果证据。

### 7. 交付完整 K2 结果并停止

按交付参考形成七段完整 K2 结果。所有段落使用同一组事实，未知项标记“待验证”，不补造客户原话、经营数据、技术能力或交付结果。

完整交付默认生成 K2 HTML 行动报告。按视觉框架将同一组结论写入 JSON，调用 `modules/design-value-and-launch/scripts/render_k2_value_canvas.py` 输出 `.html`，报告内嵌已填写的“价值设计画布（K2 价值主张设计）”；只需单独画布时仍可输出 `.svg`。只有另一项最大不确定性确实会改变判断时，最多增加一张对外辅助画布。再按证据依赖顺序生成三张行动卡，并用 30 天目标组织一轮可判断的价值验证，最后形成逐项可追溯的 K2 回传证据包。

对外结果先给简短判断，再在 HTML 中呈现核心画布和三张行动卡；七段证据细节继续保留，不让图像取代可追溯文字。生成失败时可用 Markdown 说明进展，但正式报告验收仍未完成。仅预览不可用时，返回已验证存在的 HTML 链接并说明未做视觉验收。

无法形成价值缺口时立即停止，不进入价值主张和交付设计；无法选出优先价值主张时，不进入最小价值单元；无法识别单一最高风险时，不设计综合试点。回传新增的确认事实、工作假设和证据缺口，并给出 `recommended_review` 供诊断层复核。本模块不自行修改 `action_stage`，不得调用其他阶段模块，也不自行进入 K3。

## 当前边界

- 不重做 K1 市场细分或客户命名。
- 不把口头兴趣、内部设想或功能清单写成客户价值证据。
- 不补造客户行动、访谈、付费、转化率或财务数据。
- 不扩展完整定价、单位经济模型、产品路线图或 K3 增长设计。
- 不把单一特殊客户成功写成可重复增长，不自行升级阶段。
- 视觉画布只是同一组 K2 判断的图形摘要；图文使用同一组事实，不用图形产生新数据、新客户或新阶段判断。

## 完成前自检

- 是否只有一个具体优先客户、一个主要场景和一个客户任务？
- 是否真实记录了当前替代方式及客户继续使用它的原因？
- 是否区分已确认事实、工作假设和证据缺口？
- 价值缺口是否是可观察的客户结果差距，而不是产品功能愿望？
- 是否默认形成 2 至 3 个候选，并用六维定性比较选出一个优先价值主张？
- 是否保留暂不选择的候选及舍弃理由？
- 最小价值单元是否同时让客户获得可观察结果、让团队获得决定性证据？
- 产品端是否只有四步，后台端是否只有五项，并明确排除范围？
- To B 是否拆开四个角色；To C 是否原样复用 K1 短标签；混合业务是否隔离两侧证据？
- 是否每轮只选择一个最可能推翻当前价值主张且能够低成本验证的最高风险假设？
- 风险试点是否要求客户真实行为和团队结果证据，并写清继续、调整和停止条件？
- 若返回 K1，是否只提出最多一个补证问题？
- 是否按固定顺序交付七段完整结果，且所有段落使用同一组事实？
- 是否交付一张已填写的核心画布，并最多增加一张与最大不确定性匹配的辅助画布？
- 是否只有三张按证据依赖排序、字段完整的行动卡？
- 30 天目标是否用于形成一次可判断的价值验证，而不是承诺完成 MVP？
- K2 回传证据包是否逐项可追溯至确认事实、工作假设或证据缺口？
- 是否严格停在 K2，只建议诊断层复核而不自行进入 K3？
