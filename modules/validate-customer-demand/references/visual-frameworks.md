# K1 可视化框架

### STP 客群收窄画布

完成候选 Segment 与 Target 初判后，完整交付默认生成并显示一份 K1 HTML 行动报告，报告内嵌 1600×1100 STP 客群收窄画布，并以绝对路径显示；只需单独画布时可将输出路径设为 `.svg`。左侧同心图固定呈现 `市场边界 → 需求/行为候选群 → 五项闸门 → 一个优先 Target`；右侧固定呈现五项 Target 闸门与四项客户问题定位字段。牛眼式同心结构只负责表达收窄过程，不替代 STP，也不用于获客渠道选择。

输入 JSON 结构：

```json
{
  "title": "本轮客群收窄主题",
  "stage": "当前项目 K1",
  "business_type": "To B | To C | 混合业务",
  "decision": "本轮必须作出的客户选择",
  "market_boundary": "[已确认|假设|缺口] ...",
  "segments": [{"label": "候选短标签", "basis": "[已确认|假设|缺口] ..."}],
  "target": {
    "label": "一个优先 Target",
    "why_selected": "[已确认|假设|缺口] ...",
    "criteria": {
      "measurable": "[已确认|假设|缺口] ...",
      "substantial": "[已确认|假设|缺口] ...",
      "accessible": "[已确认|假设|缺口] ...",
      "differentiable": "[已确认|假设|缺口] ...",
      "actionable": "[已确认|假设|缺口] ..."
    }
  },
  "positioning": {
    "context_job": "[已确认|假设|缺口] ...",
    "current_alternative": "[已确认|假设|缺口] ...",
    "difference": "[已确认|假设|缺口] ...",
    "reason_to_believe": "[已确认|假设|缺口] ..."
  },
  "non_targets": ["[已确认|假设|缺口] ..."],
  "next_evidence": ["[已确认|假设|缺口] ..."],
  "stop_line": ["[已确认|假设|缺口] ..."]
}
```

To C 的候选与优先 Target 标签均不得超过 10 个汉字。若脚本不可运行，可用同字段的 Markdown 说明进展，并明确未生成 HTML、正式报告验收未完成。仅预览不可用时返回已验证存在的 HTML 链接并说明未做视觉验收。图文必须复用同一组证据标签，不能为了画满同心图补造客群、规模或定位理由。

### 价值设计画布（K1 客户细分定位）

默认必须填写这张画布。为兼容既有表达，文中“K1 客户定位画布”仅指这一个默认的价值设计画布（K1 客户细分定位），不是另一张画布。输出时用本轮用户案例中的事实、弱线索、工作假设和证据缺口替换下列说明文字；未知项统一写“待验证”，不得原样输出说明文字，也不得为填满画布补造客户语录、数字、角色或行为。

| 目标客群 | 触发场景 | 客户目标 |
| --- | --- | --- |
| 基于本轮证据填写 | 基于最近具体事件填写 | 基于客户要实现的改变填写 |

| 待完成任务 | 痛点/阻碍 | 好结果 |
| --- | --- | --- |
| 客户必须完成什么 | 当前困难、风险或成本 | 可观察的期望改变 |

| 当前替代 | 已发生行动 | 最大证据缺口 |
| --- | --- | --- |
| 客户现在如何处理 | 时间、材料、试点、采购或付费 | 下一步必须带回什么 |

## 使用位置与边界

在 Target 初判后紧接输出已填写画布，再用一到三句话说明最关键判断和最大证据缺口。K1 只填写目标客群、场景、目标、任务、痛点、好结果、替代和行动证据；产品/服务、痛点缓解、收益创造和最终价值主张属于 K2，不能写入本画布。

## 辅助框架选择

默认画布之外，只允许选择一个最相关的辅助框架。只有该框架能改变当前判断或下一步行动时才使用；同样必须填写已知内容，未知项写“待验证”。

| 当前最大证据缺口 | 辅助框架 | 核心字段 |
| --- | --- | --- |
| 客户所思所感与行为不清 | 同理心地图 | 所见、所闻、所思所感、所说所做、痛点、收获、证据来源 |
| 行动过程或触点不清 | 客户旅程图 | 阶段、客户行动、触点、阻碍、已有证据、待验证项 |
| To B 决策链不清 | To B 角色决策链 | 使用、发起、决策、采购、否决及各自证据 |
| To C 角色关系不清 | To C 角色关系图 | 使用、影响、决策、付费及各自证据 |
| 企业付费、个人使用 | To B/To C 双路径图 | 两类客户各自的场景、任务、行为和证据缺口 |
