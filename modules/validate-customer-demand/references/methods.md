# K1 验证方法

## 选择原则

只选能解决当前最大证据缺口的一种细分或判断方法。若多个缺口同时存在，先处理会推翻客群选择或需求判断的那一个；STP 只在前述细分后用于决策收口。

| 最大不确定性 | 首选细分/判断方法 | 必须带回的证据 |
| --- | --- | --- |
| 需求何时发生不清 | 场景细分 | 最近一次具体事件、触发条件、处理过程和后果 |
| 客户真正要完成什么不清 | 任务/问题细分 | 必须完成的任务、阻碍和不行动后果 |
| 口头兴趣是否代表需求 | 行为细分（含替代行为） | 搜索、比较、临时方案、时间、人力、预算或承诺行动 |
| 同类客户为什么表现不同 | 状态细分（生命周期） | 当前经营、生活或责任状态及其变化 |
| 谁使用、决策或付费不清 | 角色细分 | To B 决策链或 To C 使用/决策/付费关系 |
| 已有候选客群需要取舍 | STP 决策收口 | 候选 Segment、Target 取舍证据和客户问题定位假设 |

## 业务分流与证据地图

先按本轮对象分别处理 To B、To C 或混合业务；混合业务必须先选定企业/渠道客户或最终个人用户，并分别保存证据，不交叉证明。

- To B：检查行业/生态位置、业务状态、使用/发起/决策/采购/否决角色、触发事件、现有替代和采购行动。
- To C：所有 To C 对外客群名称位置（候选、Target、默认画布、回传）复用同一个不超过 10 个汉字的规范短标签；场景、行为、角色限定词进入证据列，不得用空格、标点或属性堆叠规避。内部证据地图保留生活状态、场景、任务、行为及使用/决策/付费角色，避免把一个简短标签误当作需求证据。
- 企业规模、年龄、收入等属性只有在会改变需求、决策、触达、付费或交付时才使用；否则不作为细分依据。

## 客群定位构成与标签验收

候选标签不是分析起点，而是内部定位卡的压缩结果。每个候选客群先补齐四个字段：

| 定位字段 | 要回答的问题 | 证据边界 |
| --- | --- | --- |
| 身份/状态 | 谁在什么生活、责任或经营状态中 | 属性必须能解释需求或决策差异 |
| 任务场景 | 什么事件触发了必须完成的任务 | 优先使用最近一次具体行为 |
| 购买动机 | 为什么现在愿意搜索、比较、试用或付费 | 动机未出现行动时只是工作假设 |
| 取舍标准 | 客户在哪些风险、成本、体验或身份价值之间做选择 | 必须由比较、放弃、复购或付费证据校正 |

对外标签优先压缩“可识别的人/组织 + 最具区分度的动机或状态”，并能让业务人员用观察条件找到这类人。标签本身不必塞入全部场景，但完整场景、行为和证据必须保留在定位卡和画布中。

下列信息可作为证据字段，但不能单独成为客群定位：

- 技术路线：“智电”、“混动”或“燃油”主要回答偏好什么产品，没有回答谁为什么买。
- 购买渠道：“线上”或“线下”只说明发生在哪里，不说明客户的身份、动机和取舍。
- 产品品类：“购金客”、“车主”等只重述品类，无法区分不同需求。
- 宽泛属性：“中产”、“年轻人”、“女性”等只有在它们会改变任务、购买动机或取舍标准时才可进入标签。

若一个标签只能回答“买什么”或“从哪里买”，则退回四字段定位卡重做；若定位卡中的动机仍无行为支持，则显式标为工作假设。

## STP 决策收口与反向筛选

STP 不是先验分类或打分表，而是前述细分后的收口：

- Segment：列出候选细分及其已知证据和缺口。
- Target：明确优先、备选、暂不选择 Target 及各自取舍证据；每个优先 Target 同时给出相似但应排除的非目标客户和可验证理由。
- Position：只输出客户问题定位假设，即目标客户在特定情境下要完成的任务、受阻点或不行动后果；不输出产品/服务定位、痛点缓解、收益创造或价值主张，这些属于 K2。

不使用没有同口径基线的权重或分数。优先级应能被新的场景、行为、角色或承诺证据推翻。

### Target 五项有效细分闸门

对每个优先 Target 逐项给出证据状态。五项用于发现缺口和比较取舍，不是把主观判断包装成总分。

| 闸门 | K1 要回答的问题 | 不成立或缺证据时 |
| --- | --- | --- |
| 可衡量 Measurable | 能否用一致口径识别这类客户及其价值或数量边界 | 标记缺口，不编造市场规模 |
| 足够价值 Substantial | 该群体是否足以支持继续投入验证或服务 | 收窄或暂不选择，不用“大市场”替代证据 |
| 可触达 Accessible | 是否能在可接受条件下找到、接触并继续验证 | 先验证触达路径，不把渠道曝光当需求 |
| 可区分 Differentiable | 需求、行为或反应是否与其他候选群有可观察差异 | 合并无差异客群或更换细分变量 |
| 可行动 Actionable | 团队能否为该群体设计并执行下一项验证 | 若不能行动，先解决对象或证据定义 |

闸门只决定“是否值得把这个 Segment 作为优先 Target 继续验证”，不证明需求、付费或 K2 价值主张已经成立。

### To B 嵌套细分

To B 客群仍过宽时，采用 Bonoma–Shapiro 的嵌套思想，从外到内逐层检查：

1. 企业特征：行业、规模、地区或生态位置，但只保留会改变需求或采购的变量。
2. 运营变量：技术/流程状态、能力、使用强度与当前替代。
3. 采购方式：采购职能、权力结构、决策链、政策与取舍标准。
4. 情境因素：具体应用、紧迫性、订单/项目条件与触发事件。
5. 购买者特征：关键角色的风险态度、动机、关系与决策偏好。

外层变量用于找到企业，内层变量用于解释“为什么现在买、谁能推动、什么会否决”。不得只写“中小企业”“制造业客户”就停止收窄。

### 同心收窄图的角色

使用“同心收窄图（牛眼式呈现）”表达 `市场边界 → 需求/行为候选群 → 五项闸门 → 一个优先 Target`。它是 STP 和 To B 嵌套细分的视觉结果，不是独立理论，也不是《Traction》中用于选择获客渠道的 Bullseye Framework；K1 不用它罗列或筛选获客渠道。

### 理论依据

- Kotler 与 Keller，《Marketing Management》：市场细分与目标客户识别、客户价值主张与定位属于相邻但不同的战略任务。
- OpenStax《Principles of Marketing》：有效细分采用 Accessible、Differentiable、Actionable、Measurable、Substantial 五项标准。
- Bonoma 与 Shapiro，Harvard Business Review，*How to Segment Industrial Markets*：To B 可把企业特征、运营变量、采购方式、情境因素和购买者特征排列为嵌套层级。

## 需求证据梯

证据由弱到强通常表现为：

1. 表达：赞同、兴趣、抱怨或对未来的意向。
2. 现实行为：已经投入时间、人力、数据或临时方案处理问题。
3. 验证承诺：愿意给材料、安排下一步、引荐关键人或参与试用。
4. 商业行动：进入预算、采购、合同或付款流程。

证据梯用于判断“下一个需要观察的行为”，不是通用打分表。不同业务的承诺方式不同，不自行设置固定通过数量。

## 停止线写法

用条件句而不是伪精确数字：

- 继续：同一候选客群反复出现相同场景，且出现比口头兴趣更强的行动证据。
- 调整：问题存在，但触发场景、决策人或替代方式与当前假设不同。
- 停止：在已约定的同口径观察窗口内，只反复得到礼貌性认可，而没有对应的现实行为或承诺。
