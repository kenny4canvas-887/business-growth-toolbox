# 培训与能力提升项目诊断（内部 L&D / 培训管理者视角）

> 本文件是业务体检的按需参考，不新增阶段决定权。触发条件：用户是培训管理者、内部 L&D、讲师，或想给团队／客户做「能力提升／培训」项目。

## 一句话立场

**先诊断业务卡在哪一关，再决定培训卖什么、补哪块能力；不卖通用能力课。**

培训管理者最容易犯的错，是拿一个「销售能力」「领导力」「执行力」的通用课纲去套所有客户。通用课纲的问题不在内容，在于它默认了「问题是什么」——而业务真正卡住的地方，往往和课程假设的不是同一关。业务体检先把它收窄成「这一关到底缺什么能力」，培训才有靶子。

## 使用方式

把「培训项目」当成本轮诊断对象时，业务体检照常走阶段路由；只是输出时多一层映射：**阶段 → 能力缺口 → 对应培训/工作坊 → 用什么已发生行为验证补对了**。

不要问培训管理者「你属于哪一类客户」。直接让他描述「要给谁、解决他生意里哪件事、最近发生了什么」，再判阶段。

## 阶段 → 能力缺口映射（速查）

| 业务卡在 | 真实缺口（不是课程名） | 更该做的形式 |
| --- | --- | --- |
| K0 选方向 | 团队不会用证据判断方向，只会拍脑袋 | 方向验证工作坊，不是「战略课」 |
| K1 找真需求 | 不会从已发生行为里找客户，只会做人口画像 | 客户访谈／行为验证训练 |
| K2 做最小方案 | 不会做能真实被用的最小版本，只会做大全套 | 最小方案设计与试点复盘 |
| K3 找增长瓶颈 | 不知道增长卡在获客／留存／增购哪一环 | 增长单元拆解与漏斗复盘 |
| K4 提效配资源 | 看不到收入掩盖下的成本与交付约束 | 单位经济与交付效率训练 |
| S5 稳步复制 | 盈利了但不会把标准沉淀成可复制系统 | 标准化与复制陪跑 |
| S6 经营取舍 | 不会在成熟组合里做「留／优／缩／更」取舍 | 组合取舍决策训练 |
| S7 转型建议 | 旧模式失效却不会验证新曲线 | 转型验证工作坊 |

## 输出物

1. 诊断出的阶段与唯一决策。
2. 该阶段对应的能力缺口（一句话，不写成课程名）。
3. 一个能补这块缺口的培训/工作坊形式（不展开课纲细节）。
4. 一个验证闭环：培训结束后，用哪个已发生行为证明「业务卡点真的被推动了」——不是满意度问卷，不是出勤率。

## 边界

- 本模块只回答「该补哪块能力、怎么验证补对了」，不替培训管理者写课纲、定讲师、排课程表。
- 能力缺口是「业务诊断的副产品」，不能脱离阶段判断单独卖；脱离阶段的能力课，正是本工具箱要避免的通用课。
- 培训只是手段，业务阶段才是靶子。若诊断显示问题不在能力、而在方向或机制，就明说「这不是一场培训能解决的」，不硬接成培训项目。
