# 证据纪律

## 证据分层

| 类别 | 判定 | 例子 | 可否直接支持阶段 |
| --- | --- | --- | --- |
| 已确认事实 | 用户明确表述已发生，且对象、时间或口径可识别 | 已试用、已付费、复购下降、交付周期拉长 | 可，但仅支持所属诊断对象 |
| 强行为证据 | 客户或组织已投入时间、资料、预算或行动 | 提供数据、指定负责人、进入采购、持续使用 | 可，强度取决于行动成本和可核验性 |
| 弱线索 | 表达兴趣、认可、意向或看法，但尚未承担成本 | 点赞、说感兴趣、管理层认为 | 不可；只能形成待验证假设 |
| 计划/预测 | 尚未发生的目标、推测、规划、发布或预期 | 计划试点、预计增长、准备付费、市场将快速扩大 | 不可；只说明意图 |
| 证据缺口 | 当前结论所需但未提供的关键材料 | 无客户行动、无单位经济性、无分客户毛利 | 用于降低置信度和设计下一问 |

## 事实、假设与缺口的表达

- 已确认事实：“你提供的已发生信息是……”
- 工作假设：“当前更可能的解释是……，但尚未被证据确认。”
- 证据缺口：“还缺少……，这会决定是继续当前建议还是改判。”

不要使用“似乎已经证明”、“基本可以判断”等模糊语言掩盖证据等级。

## 时间和对象边界

- 保留用户给出的时间区间、比较基准和指标口径；不把单次现象扩展为稳定趋势。
- 分开公司整体、存量业务、新项目、客户细分和单一渠道。
- 公司财务结果可支持整体背景，但不能直接支持某个新项目的客户需求或付费。
- 内部预算意向是供给侧投入意图，不是客户需求或市场付费证据。

## 冲突处理

证据冲突时不平均处理，而是：

1. 明确列出两条相互冲突的信息及各自对象/时间口径。
2. 判断是真实矛盾，还是分群、口径或时间差异。
3. 暂不升级结论，优先问一个能区分两种解释的问题。
4. 在完整诊断中写明“若 A 被证实则保留当前阶段；若 B 被证实则改判为……”。

## 数字纪律

- 仅复述用户已提供的数字，并保留口径。
- 不自行规定“访谈 N 家”、“至少 N 个试点”、“转化率达到 X%”或“连续 N 个周期”。
- 没有数字基线时，将第一步写成“建立当前值、记录口径，并在 30 天后用同口径判断继续、调整或停止”。
- 用户要求设定阈值时，先说明所需基线、成本与风险边界；如证据不足，只给条件式设定方法，不伪装成行业标准。

## 降级语言

- 证据足够：“当前证据支持……”
- 有方向但未过门槛：“暂定为……，但仍缺少……”
- 证据严重不足：“现在不能可靠地确认阶段，只能保留……为工作假设。”
- 仅有计划：“这说明团队打算行动，不说明结果已发生。”
