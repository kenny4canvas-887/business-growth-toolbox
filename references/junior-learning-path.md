# 新手学习式诊断（无业务语境 / 轮岗新人 / 无数据起步）

> 本文件是业务体检的按需参考，不新增阶段决定权。触发条件：用户是轮岗新人、管培生，或被要求判断「某业务该不该继续投入」但无业务背景、不知数据在哪。

## 一句话立场

**新手不该被要求独立下经营判断，但可以被教「问对问题 + 找到第一份证据」。**

对新手，业务体检不是决策工具，是「学会判断」的训练工具。所以交付目标从「给你决策建议」切换为「教你做一次结构化取证、学一个判断」——既不替新手编一个结论，也不甩一句「证据不足」就停。

## 触发信号

- 用户自称轮岗新人、管培生、刚接手。
- 被丢了一个「判断某业务该不该继续投／该不该砍」的任务。
- 无业务背景，说不清「谁负责、钱从哪来、客户是谁」。
- 明确「不知数据在哪、不知道问谁」。

## 交付目标切换

| 经营者自诊 | 新手学习式诊断 |
| --- | --- |
| 交付：给你决策建议 | 交付：教你问对问题 + 找到第一份证据 |
| 目标：替用户判断 | 目标：帮用户学会判断 |
| 动作：经营动作 | 动作：可独立完成的取证动作 |

## 学习式诊断三步

1. **教问对的问题**：把「这业务该不该投」翻译成 3 个可证伪的问题（对应阶段模型）——
   - 有没有真实客户行为（不是「大家觉得」）？
   - 有没有可重复的收入或使用？
   - 现在卡在哪个约束（方向／需求／交付／资源）？
2. **教去哪找数据**：给出「最小可得证据」清单——公司内部谁最可能知道（一线销售／财务／产品／运营）、哪份现成报表、哪个已有会议能旁听。不要求新手造数据，只要求他**借**数据。
3. **第一个他能独立完成的动作**：例如「约一个一线销售聊 15 分钟，记录 3 个已发生行为」，一周内拿到第一个数据点。

## 边界

- 新手不替管理层做判断、不承诺结果；工具箱只教方法、给路径，结论由有权者定。
- 若新手连「这个业务谁负责」都不知道，先明确「先找到业务负责人」，不硬推诊断。
- 证据不足时，不硬编；宁可把「三条证据」处写「当前缺口」，并给出最便宜的补证动作。
- 当新手明显需要有人带时，明确这需要导师或咨询承接，但不硬推销。

## 收口

新手带着第一份证据回来，业务体检照常复核阶段。这个过程本身就是「管理诊断」的 onboarding——教人看业务的训练，不是一次性结论。
