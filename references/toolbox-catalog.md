# 业务增长工具箱目录

## 从哪里开始

不确定业务当前卡点时，先使用“业务体检”（`advise-business-stage`）。它是唯一有权设置或修改 `action_stage` 的入口，并只选择一条当前行动路径；用户已经明确当前阶段和要解决的唯一问题时，才可直接使用相应行动 Skill。

第一次使用请看[一分钟上手](getting-started.md)，想看过程请看[完整对话演示](conversation-demo.md)。不用先学习下面的技术 ID；它们供熟练用户直接调用及维护者核对。

## 每次咨询带走什么

每次只展示当前阶段这一行的成果。成果来自相应行动 Skill 的现有交付契约，不由入口再做一套分析，也不为展示更多图表而同时加载多个模块。

| 当前问题 | 专业判断的重点 | 完整行动报告的主成果 |
| --- | --- | --- |
| K0：这个方向值得进吗 | 有市场不等于有适合你的进入位置 | 进入／暂缓／放弃判断、机会切口与最小验证 |
| K1：到底先服务谁 | 喜欢的人不一定最先购买 | 行为型客户优先级、购买触发点、暂不服务对象 |
| K2：先做什么才有人用 | 最小价值单元不是最少功能 | 最小交付方案、价值承诺、明确不做的功能 |
| K3：增长卡在哪里 | 更多流量可能放大前面的流失 | 第一增长断点图、只针对该断点的验证动作 |
| K4：为什么更忙却没改善 | 收入增长可能掩盖交付和资源损耗 | 结果损失路径、一个优先调整杠杆、本轮不优化项 |
| S5：能不能复制 | 单点赚钱不等于离开关键人还能复制 | 复制条件、带证据边界的飞轮图、扩张停止线 |
| S6：资源继续投哪里 | 收入、利润、现金与资本回报可能不同向 | 保留／优化／收缩／更新取舍表；缺数据时用明确标注的参照或示例解释 |
| S7：转型保留和改变什么 | 不是全部推倒，也不是追热点 | 保留／停止／试验清单、最小迁移验证路径 |

K0—K3 优先用于高频试用；K4、S5—S7 保持原阶段入口条件。缺少数据时成果可以是待验证假设与补证计划，不能把表格填满当作证据已经成立。

## 模块边界

| 对外名称 | 技术 ID | 何时使用 | 只解决什么 | 不做什么 |
| --- | --- | --- | --- | --- |
| 业务体检 | `advise-business-stage` | 阶段未知、证据冲突或需要正式诊断 | 当前最该做的一个经营决策 | 不同时给出多阶段方案 |
| 选方向 | `define-market-opportunity` | 已确认 K0 | 一个机会是否值得进入 | 不把趋势或能力当作客户需求证据 |
| 找真需求 | `validate-customer-demand` | 已确认 K1 | 哪类客户会在何种场景真实行动 | 不把兴趣、访谈或曝光当作已验证需求 |
| 做最小方案 | `design-value-and-launch` | 已确认 K2 | 最小价值闭环能否被真实使用 | 不在价值证据不足时扩大交付 |
| 找增长瓶颈 | `build-repeatable-growth` | 已确认 K3 | 哪个获客、留存或增购环节阻断重复 | 不把一次性增长当作可重复增长 |
| 提效配资源 | `optimize-business-model-and-resources` | 已确认 K4 | 哪个模式、成本、交付或资源瓶颈应先处理 | 不用汇总财务替代增长单元证据 |
| 稳步复制 | `scale-with-control` | 已确认 S5 | 已盈利经营单元是否具备可控复制条件 | 不把飞轮故事、高毛利或规模愿景当作已发生证据 |
| 经营取舍 | `manage-business-tradeoffs` | 已确认 S6 | 成熟经营组合中哪个单元应保留、优化、收缩或更新 | 不处理新业务需求验证、盈利复制或旧模式重构 |
| 转型建议 | `guide-business-transition` | 已确认 S7 | 旧模式失效后保留什么、停止什么及哪个新曲线假设值得最小验证 | 不把趋势、管理意图或新项目当作已证实转型 |

## 组合规则

1. 业务体检设置或修改 `action_stage`；每轮最多一个行动 Skill。
2. 行动 Skill 之间不得直接调用，也不得并行输出多套阶段建议；它们只回传证据和 `recommended_review`。
3. 用户要求完整交付时，仍按既有契约生成“诊断 HTML + 当前阶段行动 HTML”；不会因工具箱目录而生成七份行动报告。
4. 直接调用行动 Skill 时，先检查其阶段入口；入口不成立时返回业务体检重新判断，而不是猜测或串联其他行动 Skill。

## 共享辅助能力

“证据台账”和“报告生成”是内部辅助能力，不是另一个对外诊断或行动 Skill。它们分别负责证据可追溯性与 HTML 交付，不能与业务体检或行动模块竞争。详细边界见 [共享辅助能力边界](helper-boundaries.md)。

## 新增模块门槛

只有同时满足以下条件才新增对外模块：有清晰而不同的用户任务、独立的输入/输出与停止边界、至少三个重复出现的案例证明其带来可衡量的成本或质量收益、不会复制 K0—K4 的决策，并附带可验证的契约测试。否则优先扩展现有模块的参考资料，而非增加路由。
