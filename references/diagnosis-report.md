# 诊断 HTML 报告契约

## 适用范围

快速初判不生成 HTML。只有内部顾问模式，或用户明确要求完整诊断、详细报告或 HTML 时，才生成独立静态报告。

报告直接消费版本 `1.0` 的阶段交接对象，可选接收脱敏 `evidence_refs`。完整交付必须接收一个指向当前 Kx 行动 HTML 的 `stage_attachment`；诊断页与行动页分开生成并互链。不得嵌入客户名单、合同全文、账号、密钥或私人原始材料。

完整交付固定为“诊断 HTML + 当前阶段行动 HTML”。缺少对应 K0—S7 行动 HTML 时不得宣称完整交付；只生成当前阶段的一份行动报告，不得同时生成七份行动报告。若用户只要求快速阶段初判，则两份 HTML 都不生成。

所有正式业务测试和案例验收一律按完整交付执行；快速初判的文本例外不适用于业务测试。测试记录必须能追溯诊断输入、当前阶段行动输入及两份 HTML，未知证据继续标记为“待验证”。

## 固定结构

交付前先用对话短摘要说明本次取舍；不增加第三份报告或改动现有 JSON schema。诊断页回答“为什么先解决这个”，行动页回答“具体怎么解决”，行动页主成果按[专属成果目录](toolbox-catalog.md)对应当前阶段呈现。两页使用同一交接对象的范围、事实等级和阶段判断；诊断层发现需改判时先复核并更新输入，再生成匹配的两页，不能仅改其中一页的阶段标签。

首屏 `verdict` 用现有 `decision` 及阶段诊断字段说明“原本想做什么 → 当前先做／暂不做什么 → 原因与改判条件”；用户没说原计划时明确未提供，不编一项旧决定来制造反差。交付消息分别链接两份已生成文件并说明用途，收口附[继续摘要](getting-started.md)。文件不可生成、不可访问或缺少其中一份时说明实际状态，不把文本示意当作完整交付。

根节点使用 `data-report="stage-diagnosis"`，并依次包含：

1. `verdict`：首屏显性标记“核心判断”，呈现双层阶段、唯一经营决策、诊断层复核建议及可纠正边界。判断必须写出从表面问题到真实问题的因果链，明确本轮先做什么和本轮不做什么，并给出会撤回或调整结论的改判条件。
2. `stage-matrix`：只用 K0—K4 说明每一阶段如何帮助业务，并突出当前行动阶段；S5—S7 背景只留在结论卡，不与五个行动 Skill 混排。不生成分数或虚构置信百分比。
3. `current-stage-diagnosis`：解释当前阶段为什么成立、本阶段唯一决策、最多五个阶段关键问题及其当前答案／证据状态，以及进入下一阶段的证据条件。内容来自 `stage_payload.stage_diagnosis`；未知项写“待验证”，不能只显示阶段代码。
4. `scope-boundary`：产品／服务、地区、渠道／运营主体、收入、客户数据与履约责任。
5. `evidence-boundary`：已确认事实、工作假设、证据缺口和可选脱敏索引。
6. `single-route`：诊断入口、本轮唯一行动 Skill、诊断层复核。
7. `evidence-loop`：30 天改变目标、回传判断与停止／改判线。
8. `stage-attachment`：只链接行动 Skill 已生成的当前阶段 HTML，不复制其内容。

## 安全与展示

- 使用 `scripts/render_stage_diagnosis_report.py --input INPUT.json --output OUTPUT.html`。
- 完整报告必须提供 `stage_payload.stage_diagnosis` 及至少一个有效阶段问题；缺失时渲染失败，不用通用问题伪装成完整诊断。
- 所有用户文本必须转义；不生成脚本、外链、跟踪代码或远程资源。
- 阶段附件只接受当前报告可达的本地相对路径；不安全路径降级为文字说明。
- CSS 内嵌，桌面、窄屏和打印均可读；未知项显示“待验证”。
- HTML 是诊断层证据摘要，不证明阶段已正式升级、经营结果已发生或行动 Skill 的方法已经执行。
