# 潜在客户视觉输出契约

## 使用时机

用户需要简版视觉画布时使用本契约。只要快速初判时先给短决策摘要，不自动生成画布；用户已请求完整诊断或详细报告时直接交付七段简报与双 HTML，不叠加此简版流程。

默认结果控制在一次屏幕滚动可以看到主要判断和行动，不重复解释相同证据。

## 1. 诊断卡

用四行以内说明：

- 诊断对象。
- 阶段：双层场景写成“公司背景 S7 + 当前项目 K0”。
- 当前必须决定的一件事。
- 置信边界：明确这是可纠正初判，以及什么信息最可能改判。

## 2. 已填写画布

每次只生成一张“商业阶段行动画布”。先将结果写成 JSON，再运行：

```bash
python3 scripts/render_business_canvas.py --input /absolute/path/canvas.json --output /absolute/path/canvas.svg
```

JSON 的 `sections` 必须恰好提供以下六格，每格一至两条短句：

- `customer`：客户定位或当前最需收窄的客户假设。
- `value`：价值主张或客户为什么会改变现有做法。
- `activities`：当前真正关键的经营或验证活动。
- `evidence`：已确认事实；假设必须标注“工作假设”。
- `next_step`：下一项最能降低不确定性的验证。
- `stop_line`：出现什么证据时暂停、调整或停止放大。

字段不足时填写“待验证：具体缺口”，不补造数字。生成后使用绝对路径显示图片。若运行环境不能生成或显示 SVG，降级为一个两行三列的紧凑 Markdown 表格，不因此展开长报告。

## 3. 三步行动

只给最重要的三步，按依赖顺序排列：先降低最大不确定性，再形成可比较证据，最后决定继续、调整或停止。不要把三个并行愿望写成行动。

### 行动卡固定模板

每个字段只写一个短句，不在卡片前后补充解释段落。标题以动词开头；所需对象或数据直接写入“现在做什么”。

### 行动 N｜动词开头的短标题

> **为什么做：**说明它要验证什么或避免什么误投。
>
> **现在做什么：**说明一个具体动作，以及所需对象或数据。
>
> **完成标志：**说明要带回什么可观察证据；没有基线时先建立基线。

**复制这句话继续：**

```text
请根据我接下来提供的真实业务信息，帮我完成当前行动，并更新行动画布。
```

实际提示词必须替换通用句，写明当前业务对象、用户接下来要提供的材料和期望产物。例如：“请根据我接下来提供的 5 条真实客户评论，帮我区分购买理由、未满足问题和待验证价值主张，并更新行动画布。”提示词只写一句，不重新复述诊断。

## 4. 相似案例片段

从案例片段资源中最多选一个，只展示背景、关键转折和可借鉴提示。明确说明案例仅用于理解方法，不代表用户会得到相同结果。没有真正相似的案例就不展示。

## 5. 继续选择

三张行动卡之后只提供三个短选项：

1. `自行验证`：带走画布和三步行动。
2. `继续深挖`：从客户定位、价值主张、增长瓶颈或组织承接中选择一个专项。
3. `了解更多`：了解 BMI 兴远咨询、BMI Kenny 和当前问题适配的咨询方式。

最后单独写：“回复 `1`、`2` 或 `3` 即可，也可以直接说你的下一步。”收到选择后只进入对应分支，不要同时展开三个分支。用户已请求继续深入时直接执行，不再要求回复数字。选择自行验证或稍后继续时，按[使用与复盘指南](getting-started.md)交付已填写的继续摘要。

当前没有预约链接。只有用户选择 `3` 或明确要求咨询信息时，才提供邮箱 `kenny@xyconsultant.cn`，不生成假链接或其他联系方式；对外签名只显示 `BMI Kenny`。

## 完成前检查

- 首屏是否先看到判断而不是方法说明？
- 是否只展示一张已填写画布？
- 每项行动是否都有为什么做、现在做什么、完成标志和可复制提示词？
- 是否避免重复七段报告中的相同内容？
- 事实、工作假设和证据缺口是否在画布中仍然清楚？
