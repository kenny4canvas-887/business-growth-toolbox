# 按需图解经营汇报

## 何时生成

只有用户明确索要报告、接受收尾邀请，或在继续菜单中选择4时才生成。未选择、拒绝、结束或换话题时不生成，不重复邀请。不必跑完全部阶段；复用已有分析，不为了报告重新诊断或重跑模块。

## 交付结构

使用 `../assets/management-brief.html`，按内容压缩为1—3页。模板是图解排版起点，不能把固定图形当成业务事实。围绕同一个核心经营决定组织全文：

1. **方向与取舍**：当前阶段及依据、核心挑战、目标客户与价值、已有基础、经营方向；用定位关系图和保留／优先／暂缓三栏。
2. **经营模式与能力**：客户价值怎样变成收入、贡献与现金；用经营链路或循环图呈现因果关系，列出需要调整的产品、渠道、交付、组织及负责人。一次性项目可用线性链路，不能硬套复购循环。
3. **实施与决策**：30天目标，必要时延伸60／90天；任务、负责人、验证证据、继续／停止门槛；列出管理层需要批准的方向、预算上限与资源。没有预算数据写“待批准／待测算”，不能代定金额。

面向老板重点呈现经营调整与资源取舍；面向投资人补充已有商业模式、资金用途、里程碑及关键风险。缺少市场、财务或融资资料时注明缺口，不把这份短报告冒充完整融资BP，不承诺收益。

## 填写与证据

- 模板所有 `{{字段名}}` 都必须替换；未提供的事实写“待验证／未提供”，待批准事项写“待批准”。复制模板后再填写，不覆盖通用模板。
- `CURRENT_STAGE` 用客户听得懂的阶段描述并附依据，不只写内部阶段代码。`CORE_DECISION` 是本轮唯一核心决定。
- `POSITION_*` 是基础、客群价值与经营目标；`LOOP_*` 是收入与交付链路；`PHASE_*` 是分期行动、责任、证据门槛；其他字段按所在标题填写。
- 定位图 `BASE / VALUE / GOAL` 分别对应左框／中圆／右框；经营图 `UNIT` 为中央经营单元，`ACQUIRE / PAY / DELIVER / CONTINUE` 为四个环节，`FEEDBACK` 为反馈说明；`ACCESSIBLE_DESCRIPTION` 为整张图的文字替代说明。行业不适用时调整节点名称与箭头。
- 图中节点标题建议不超过10个汉字，说明不超过18字；长内容移至图外。优先删掉重复文字，不能缩小到难读。
- 区分已确认事实、工作假设和证据缺口；建议写成明确行动，但确定性不能超过证据。当前阶段未定时写“阶段待复核”，不能借排版完成阶段升级。
- 每页 `EVIDENCE_*` 简短记录依据与尚待验证事项。仅使用已授权的脱敏摘要，不嵌入客户原始访谈、名单、合同或凭据。
- 有真实数值才用数据图，注明时间、口径和来源；否则用关系、流程与路线图，不造分数、增长曲线或收益预测。

## 文件与验收

交付自包含HTML，内嵌CSS和SVG，无外链、脚本或追踪；替换文本时做HTML转义。具备本地导出能力时可同时给PDF，否则如实交付HTML及浏览器打印方法，不承诺已生成PDF。正文呈现客户业务，内部字段名与工具清单不进入交付。

交付前检查：没有未替换占位符；核心决定、30天目标、负责人、资源请求、停止条件与证据缺口均可找到；图文结论一致；打印1—3页、无裁切／重叠，窄屏可读，链接真实可达。只链接实际生成的文件，并用一句话说明需管理层决定什么。
