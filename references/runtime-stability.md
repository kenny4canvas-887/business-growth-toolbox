# 运行稳定契约（Runtime Stability）

> 上架前补齐的「运行稳定」参考。说明十个渲染器的运行契约与错误处理行为，供评审与维护者核对。入口「业务体检」在需要时按需读取。

---

## 1. 接口契约

- **输入**：`--input <path>` 指向一个 UTF-8 编码的 JSON 文件，顶层必须是对象。
- **输出**：`--output <path>` 指向渲染产物；`.html` 输出完整报告页，`.svg` 输出矢量图（部分模块同时支持两者）。
- **调用方**：由「业务体检」入口在生成诊断后调用；输出为本地相对路径的 HTML／SVG，报告间用**安全相对链接**互链。
- **链接安全**：仅接受同目录 `.html` 作为附件（`stage_attachment`），拒绝 `..`、绝对路径、query／fragment、非 `.html` 后缀，避免越界读取。

## 2. 依赖与确定性

- **零外部依赖**：仅用标准库 `argparse / json / html / re / pathlib / typing`，不引入任何第三方包。
- **无网络**：渲染过程不发任何网络请求，离线可跑。
- **确定性**：相同输入 → 相同输出；不依赖时间、随机、环境变量或文件系统状态。
- **兼容 Python**：3.9+（已用 `from __future__ import annotations`，类型注解不影响运行时）。

## 3. 输入校验

- 渲染函数对必填字段做**非空／类型校验**，缺失即抛 `ValueError`，不静默填默认值掩盖问题。
- 证据字段必须以 `[已确认]`／`[假设]`／`[缺口]` 前缀开头，否则报错——这是证据分层不被绕过的关键。
- 可选字段缺失时给出明确兜底文案（如「待验证」），而非崩溃。

## 4. 错误处理与降级（核心）

所有渲染器的 `main()` 统一行为：

1. 捕获 `OSError`（文件读写）、`ValueError`（校验失败）、`json.JSONDecodeError`（输入非 JSON）以及通用 `Exception`。
2. 向 **stderr** 打印清晰中文原因，例如 `render failed: <原因>`。
3. **写一个最小降级 HTML 到 `--output`**：标题「渲染未成功／诊断报告未能生成」+ 原因 + 「完整判断以对话文本为准」。保证产物文件始终存在，**交叉链接不断**。
4. 以**非零状态退出**（`return 1` / `SystemExit(1)`），使调用方（业务体检入口）能感知失败并按降级协议处理。

> 设计意图：渲染失败**绝不抛未捕获 traceback**，也绝不产出半成品；要么成功产出，要么产出诚实的降级页并明确报错。

## 5. 输出目录

- 自动创建 `--output` 的父目录（`mkdir(parents=True, exist_ok=True)`），调用方无需预建目录。

## 6. 调用方降级协议（业务体检入口侧）

当某渲染器非零退出时，「业务体检」执行：

- 向用户**复述确切错误原因**，不隐藏；
- 仍交付**文本版诊断**（判断、下一步、证据边界），不因图表失败而整体中止；
- **不链接缺失文件**；若另一份报告依赖它，明确说明该附件未生成；
- 若模块无法加载，回退到根诊断层引导，并说明该模块未应用。

## 7. 回归验证（上架前）

- 十个渲染器均在**有效输入**下成功产出 HTML／SVG。
- 均在**故意错误输入**（空对象、缺必填字段、非 JSON、坏路径）下非零退出并写出降级页，**无一抛 traceback**。
- 交叉链接在有效路径下互链正常；四类非法链接（越界 `..`、绝对路径、query、非 `.html`）全被拒绝。
- 详细回归记录见发布前核对清单与 `outputs/business-growth-acceptance/`。
